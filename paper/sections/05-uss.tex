\section{New USS Construction and Security Proofs}
\label{sec:uss}

We now instantiate the repaired model of Section~\ref{sec:model-repair}. The construction combines KHVC with shared-polynomial Ring-LWR payload bodies, independent RLWE-encrypted file masks, and RISE restricted to constant-size openings. After specifying the payload encryption and the complete USS algorithms, we prove full adaptive confidentiality and OF-PTXT integrity. Local component simulations are distinguished explicitly from the game-level theorems.

\subsection{Optimized Ring-LWR/RLWE Instantiation}
\label{sec:optimized-uss}

For a 32-byte random $\nu$, hash $m\parallel\nu$ with SHA-256 and decode the result as a little-endian integer reduced into the BLS12-381 scalar field. Denote this file digest by $\mathsf{COM}(m;\nu)$. $\mathsf{COM}$ is binding in the random-oracle model. Let $P_i=[(f(\tau)-h_i)/(\tau-\omega^{i-1})]_1$ denote the unblinded opening for the digest vector $(h_i)_{i=1}^n$, and let $W_i=[Z(\tau)/(\tau-\omega^{i-1})]_1$.

\paragraph{Setup and epoch keys.}
Generate the KHVC parameters and derive the shared $a_b$ sequence as needed. The full epoch secret consists of a nonzero RISE scalar $k$, a Ring-LWR secret $s$, and an RLWE header secret $\mathsf{sk}_H$. The public keys are $Y=kg_1$ and $\mathsf{pk}_H$.

\paragraph{Store.}
For slot $i$, sample $\nu_i$, set $h_i=\mathsf{COM}(m_i;\nu_i)$, and encrypt $m_i\parallel\nu_i$ with the masked body scheme. Interpolate $f$ on the digest vector. Sample independent scalars $\rho,\beta$ and compute the public commitment
\[
 C=[f(\tau)]_1+(\rho+\beta)[Z(\tau)]_1 .
\]
Output the public handle $\mathsf{sb}=C$, the private client state $\mathsf{cst}=(C,\beta)$, and the repository. The server holds an encryption of $P_i+\rho W_i$ under RISE, together with each payload ciphertext. The client need not retain $\rho$. Only $C$ is visible to the server and to the confidentiality adversary.

\paragraph{Rev.}
The client decrypts the payload and RISE opening at the requested slot, rejecting malformed records, and recomputes $h_i$. It adds $\beta W_i$ to the decrypted opening and verifies against its current trusted $C$. It returns the plaintext only on acceptance.

\paragraph{FileUp.}
The client performs the same checks as Rev on the old slot against its current $C$, aborting without modifying its state on failure. It samples a nonce for the replacement, computes $h_i'$, and sets $d_i=h_i'-h_i$ using the verified digest. Let $f_d=d_iL_{i-1}$. Independently sample an opening blind $\eta\gets\mathbb F_p$ and a fresh private $\beta'$, the client sets
\[
 C'=C+[f_d(\tau)]_1+(\eta+\beta'-\beta)[Z(\tau)]_1.
\]
It sends the slot, $d_i$, $\eta$, the RISE public key, and a fresh payload ciphertext. The server replaces the payload and uses the one-hot formula to add encryptions of the openings of $f_d+\eta Z$ to all encrypted openings. Thus the server-side opening blind evolves as $\rho\leftarrow\rho+\eta$. The upload increases by one 32-byte scalar. The new client state is $\mathsf{cst}'=(C',\beta')$. A disclosed FileUp transcript consists of the old record on the wire and the replacement message, hence includes $d_i$ and $\eta$, but excludes $\beta$, $\beta'$, and uncommunicated randomness. The client request and response for the old file scale with the size of that file, and the update message scales with the new file size. Neither depends on $n$.

\paragraph{KeyUp.}
The epoch token contains the RISE token, $\Delta$, the RLWE switching key, and the new header public key. It is reusable across repositories in the same epoch. For a given repository the client also samples an independent public opening shift $\xi\gets\mathbb F_p$ and a fresh private offset $\beta'$. The server updates each RISE ciphertext under the epoch token and adds $\xi W_i$ to its second component. Its plaintext is then $P_i+(\rho+\xi)W_i$. The client sets
\[
 C'=C+(\xi+\beta'-\beta)[Z(\tau)]_1 .
\]
For each file the server independently samples $\delta_i$ and wide noise $z_i$, updates the body with $\Delta+\delta_i$, and returns the noised header $(u_i',v_i'+z_i)$ specified in Section~\ref{sec:ue}. The client's new state is $\mathsf{cst}'=(C',\beta')$. Under the wide-noise baseline, each file header is $1{,}048{,}576$ bytes, the switching key is $64$ MiB, the new header public key is $1$ MiB, and the shared token totals $68{,}161{,}616$ bytes when the 80-byte RISE token and 4096-byte $\Delta$ are included. There are 32 additional bytes per repository for $\xi$. A KeyUp transcript contains the shared token and repository-specific opening shifts, but no $\beta$ values, local random coins, or transport-level routing information. $\mathsf{KeyUpTrans}$ returns the shared token and shifts as an unordered collection, with no input or output labels identifying the challenge repository.

\paragraph{Why $\beta$ is not public.}
The public/private separation is necessary for the confidentiality statements, not merely an implementation detail. If old and new private offsets were exposed together with the corresponding stubs, an observer could compute $D=C-\beta[Z(\tau)]_1$ and $D'=C'-\beta'[Z(\tau)]_1$. For a single rotation with disclosed $\xi$, it could test $D'=D_b+\xi[Z(\tau)]_1$ for each candidate old repository $b$, without any epoch-key leakage. Our games therefore use the interface specified above: public handles $C$ are returned, while repository-level client offsets remain private even under $\mathsf{KeyCorr}$.

\begin{lemma}[Joint simulation of a hidden rotation with real next-key disclosure]
\label{lem:hidden-rotation}
Consider one KeyUp whose transition token is never returned, while the actual new epoch secret may subsequently be revealed. Let $m$ be the total number of ordinary file records returned from all repositories sharing this edge. The simulator knows the real new secret, the body-key difference $\Delta$, the integer-lift history of every file mask, and all wide noise it sampled on earlier rotations, but need not know the old header secret. For file $i$, let $\mu_i$ be its accumulated integer-lift mask after this rotation. In a real updated header $(u_i',v_i')$, suppose
\[
 v_i'-x_{\mathrm{new}}u_i'-S\mu_i=z_i+\epsilon_i,
 \qquad \|\epsilon_i\|_\infty\le B_{\mathrm{old}},
\]
where all operations on the left are modulo $Q_H$ and the residual is center-lifted. Then the simulator can jointly generate every returned updated header and body, together with the real new secret, so that the generated joint distribution $\mathcal D_0$ is within statistical distance
\[
 \operatorname{SD}(\mathcal D,\mathcal D_0)\le
 \frac{mN_H B_{\mathrm{old}}}{2L+1}
\]
of the real joint distribution $\mathcal D$.
\end{lemma}
\begin{proof}
Under the real new public key, generate raw RLWE encryptions of zero and retain only their first components. A gadget message occurs only in the second component, so these first components have exactly the real switching-key distribution. Combine them with the old public first components and the fresh-header first components exactly as in KeySwitch to obtain every $u_i'$. The unused switching-key second components are never returned because the token is hidden. In particular, the simulator does not perform KeySwitch with zero second components, which would lose the old-secret message-cancellation term.

Instead, sample the real $\delta_i$ and $z_i$, update each body with that same $\delta_i$, and directly synthesize the second component as
\[
 v_i'=x_{\mathrm{new}}u_i'+S\mu_i+z_i\pmod{Q_H}.
\]
This is efficient without the old header secret, gives a valid header for the correct accumulated mask with zero non-wide residual, and preserves the exact joint distribution of all first components and bodies. In the real distribution the new-secret phase after removing $S\mu_i$ is $z_i+\epsilon_i$; in the simulation it is $z_i$.

Condition on the old records and all switching-key coins. For an integer shift $d$, shifting the uniform distribution on $[-L,L]$ changes it by statistical distance at most $|d|/(2L+1)$. Sum over the independent coefficients of the $m$ independently noised polynomials; no independence assumption on the old residuals $\epsilon_i$ is needed. Reduction modulo $Q_H$, revelation of the real new secret, and joint observation of the bodies are postprocessing and cannot increase statistical distance.
\end{proof}

For repeated hidden rotations, the simulator subtracts its own recorded wide-noise history, so only the remaining non-wide residual must be masked at the next step. The bound $B_t$ in Section~\ref{sec:ue} therefore applies without increasing $L$ to cover all previous wide noise. With $N_H=16384$, $D=64$, $L=2^{204}$, at most 256 returned files per edge, and at most 127 applications satisfying the lemma's premises, the accumulated statistical-distance bound is approximately $2^{-130.12}$. This accounting covers only the hidden-rotation replacements. It neither embeds an effective body key in a Ring-LWR challenge nor completes the USS opening-layer reduction.

\subsubsection{Adaptive confidentiality in the full closure-revised game}
\label{sec:adaptive-full}

The proof below does not restrict any oracle query. In particular, keys may be exposed after the challenge in components disconnected from every directly exposed challenge ciphertext, and FileUp transcripts may be disclosed long after they were created. The only parameter condition is the deterministic correctness budget, which is chosen as a function of the permitted number of rotations; the concrete parameters in Section~\ref{sec:ue} instantiate that condition for 127 rotations of one file version.

\begin{theorem}[Full adaptive confidentiality]
\label{thm:adaptive-full}
The construction satisfies IND-DD-UP, IND-FileUp-CPA, and IND-REENC-CPA in $\mathsf G_{\mathrm{cl}}$ under DDH in $\mathbb G_1$, decisional Ring-LWE for the stated header parameters and sample counts, multi-sample decisional Ring-LWR with one secret per file version, and the random-oracle model. The theorem includes adaptive key and token exposure, delayed ChaFTCorr, repeated rotations, and subsequent real-key disclosure in every component allowed by the closure rule.
\end{theorem}

\begin{proof}
We use a sequence of games and treat every query online. Fix polynomial upper bounds $E$ on created epochs, $V$ on fresh file versions, $R$ on file rotations, $M$ on produced opening ciphertexts, and $Q_{\rm ro}$ on random-oracle queries. Let $\epsilon_{\rm RLWE}$, $\epsilon_{\rm RLWR}$, and $\epsilon_{\rm DDH}$ bound the corresponding multi-sample hops below. If $\mathcal I=\varnothing$, omit the active-payload and active-opening replacements: in IND-DD-UP the two stores can be coupled identically, while IND-REENC-CPA still uses the key, stub, and opening-state alignment below because the old repositories can have different private offsets. The following active-record steps describe $\mathcal I\ne\varnothing$. The simulator maintains a logical table of plaintexts, nonces, digests, masks, opening scalars, and private offsets, and a wire table of every repository record, token, stub, and transcript. It answers FileUp from the logical table and repeated requests from the wire table. No already returned value is resampled.

\paragraph{1. Protected components are implied by the game, not imposed on it.}
At the end of a non-trivial-win execution put $P=\operatorname{Reach}_{G_{\mathcal T}}(\mathcal C)$. A connected component $J=[\ell_J,r_J]$ of $P$ is an interval. No key of an epoch in $J$ is exposed, and every transition token crossing the boundary of $J$ is withheld: otherwise closure would put the adjacent epoch in $J$. Conversely, a disclosed transition internal to $J$ is allowed and must be simulated. These statements follow from the final game check and do not reject or restrict any adversarial query.

If the key immediately to the right of $J$ is exposed, the connecting token is hidden. An active challenge record cannot be returned in that exposed epoch, since doing so would add that epoch to $\mathcal C$ and cause a trivial win. Ordinary records, including records whose slots have left $\mathcal I$, can still be returned and must decrypt correctly under that real key. This is the boundary case included explicitly below.

We process components from left to right. Before creating any record that could belong to the next component, the reduction guesses its endpoints $(\ell_J,r_J)$, with a sentinel denoting that no further component occurs. In particular, the first guess is made at setup, and each succeeding guess is made before epochs to the right of the preceding guessed component are simulated. Thus a component whose first direct exposure is caused much later by ChaCTCorr or delayed ChaFTCorr is nevertheless in the protected regime from the creation of all its records. A direct exposure inconsistent with the already processed components and the guessed next interval, a key request inside any guessed protected interval, disclosure of a token crossing any guessed protected boundary, or a trivial win causes an immediate abort to an output independent of the challenge bit. A delayed exposure inside an already processed component is legal and is answered from its fixed wire log. The same independent-output abort occurs if the final next component of $P$, or the absence of one, differs from the guess. A correct guess never triggers these query-triggered aborts in a non-trivial-win execution. There are at most $(E+1)^2$ endpoint/sentinel guesses per component and at most $E$ components. Previously processed components remain in their final simulation and all records outside the current guessed interval remain real. No query is rejected in a correct non-trivial-win execution, and no returned value is changed retroactively.

\paragraph{2. Key representation inside and outside a component.}
Outside protected components, sample every epoch key in the real way and retain it for KeyCorr. Inside $J$, body secrets $s_t$ are also sampled normally; hence every disclosed internal body difference $\Delta_t=s_t-s_{t-1}$ is available. The header keys are treated by the shadow simulation in Step~3.

For RISE, choose a root public key $Y_J=k_JG$ whose secret is not needed by the simulator. For $t\in J$, sample $d_t\gets\mathbb F_p^*$, with $d_{\ell_J}=1$, and set
\[
 k_t=d_tk_J,\qquad Y_t=d_tY_J .
\]
Thus every internal disclosed ratio is the known value $k_t/k_{t-1}=d_t/d_{t-1}$. The root and all $k_t$ remain unexposed by the component invariant. The independent real keys outside $J$ are used at the two hidden boundaries. In particular, no ratio involving the unknown $k_J$ is ever computed.

\paragraph{3. Right-to-left shadow-header hybrid and the real-key boundary.}
For $t\in J$, choose a simulator-known ternary secret $\widetilde x_t$ and replace the public key by an independent uniform pair $(a_t,d_t)$. A shadow encryption of $\mu$ is
\[
 (u,\;u\widetilde x_t+e+S\mu),\qquad u\gets R_{Q_H},\quad e\gets\{-1,0,1\}^{N_H}.
\]
A raw gadget encryption has the same form with $S\mu$ replaced by the unscaled gadget message. The plaintext masks $\mu$ themselves are not changed.

The epochs are converted from $r_J$ down to $\ell_J$. For $t<r_J$, epoch $t+1$ has already been converted, and the outgoing switching key supplied by the induction encrypts $\widetilde x_t$ under $\widetilde x_{t+1}$. It therefore requires no knowledge of the real $x_t$. At an internal incoming edge, the inductively chosen gadget message is $\widetilde x_{t-1}$; at the left boundary it is the known real $x_{\ell_J-1}$. Thus every message needed by the reduction is known. Internal tokens may be disclosed and are returned from the wire table. Before the predecessor epoch has been converted, an internal updated record is only a computational wire placeholder and need not yet decrypt to its final mask. No key in $J$ is exposed and honest FileUp uses the logical table, so this intermediate state is never used for an honest decryption. Once the predecessor is converted, the gadget message and the predecessor record agree, and the final internal ordinary headers decrypt correctly under their shadow secrets.

For epoch $t$, first replace $(a_t,a_tx_t+e_t)$ by a uniform pair using one-sample Ring-LWE. Consider each fresh public-key term, including a file-header term or a raw gadget term,
\[
 (a_tr+e_1,\;d_tr+e_2+\mathrm{msg}).
\]
With uniform $(a_t,d_t)$, its first two unshifted parts form a two-sample Ring-LWE instance under the fresh secret $r$. Replace the term by a uniform pair, and then replace that pair by $(u,u\widetilde x_t+e+\mathrm{msg})$ using one-sample Ring-LWE. Message addition, KeySwitch, addition of the independently sampled wide noise, and all body operations are public postprocessing. Applying this procedure to the incoming switching key, every current fresh header, and every refresh term converts epoch $t$ completely to the shadow regime. The outgoing internal token supplied by the induction is unchanged. There are at most $E+DE+V+R$ such public-key, gadget, fresh-header, and refresh hops in a component.

The right boundary $r_J\to r_J+1$ is handled in the same hybrid step as epoch $r_J$, rather than by claiming that equal plaintexts imply equal noise distributions. Let $m_J$ be the number of ordinary file records crossing this boundary, and let $B_J$ bound their real non-wide phase residuals after subtraction of the simulator-known wide-noise history. The simulator knows the real destination header secret, the real body difference, every integer-lift mask history, and all previously sampled wide noise. Lemma~\ref{lem:hidden-rotation} reproduces the exact first-component and body distributions, directly synthesizes each second component with the correct accumulated mask and zero non-wide residual, and incurs statistical distance at most
\[
 \delta_J=\frac{m_JN_HB_J}{2L+1}.
\]
Only the first components of the hidden switching key are retained from zero encryptions, and their second components are discarded; the lemma's direct second-component synthesis avoids the invalid zero-key KeySwitch. This remains valid when the real destination key is revealed, because it simulates the joint phase residuals, not merely the decrypted masks. Active records at the boundary are treated separately in Step~4 and are not returned under an exposed matching key. Subsequent real-key operations outside $J$ start from these valid ordinary records and follow the real algorithms exactly. Write $\delta_{\rm stat}=\sum_J\delta_J$ over all processed components.

\paragraph{4. Active payload replacement and exit from the active set.}
After Step~3, replace every active fresh file header and every active rotated header by an independent uniform pair, using the same Ring-LWE hops. No exposed key in $J$ has to decrypt such a record. For each active body version, apply one multi-sample Ring-LWR hybrid with one secret for all its blocks. The secret is $w=s_t+\sigma$ for a fresh version and $w=\Delta+\delta$ for a rotation; in either case it is uniform, and the public inputs are the shared $a_b$. Replace all $(a_b,F_w(b))$ for that version by uniform rounded-ring elements. The new body is uniform conditional on the preceding wire body and on a disclosed internal $\Delta$. Other files retain their independently sampled masks on the same public $a_b$. At most $V+R$ body hybrids occur in a component.

If FileUp overwrites an active slot, that slot leaves $\mathcal I$. Its new plaintext comes from the same adversarial request in both worlds, and its fresh client nonce is sampled with the real distribution (and is common in the two-world coupling). Generate a fresh, correctly decryptable ordinary payload and a fresh valid opening from the logical table; do not continue to update the sanitized ciphertext. This refresh step has exactly the real distribution: in the unsanitized game the fresh FileUp encryption randomness makes the resulting record a fresh encryption of its new contents, independent of the old active record. Subsequent rotations and updates of this exited slot use the ordinary path.

While a slot remains active, Next and FileUp withhold its record whether or not the destination key is exposed. A later direct exposure by ChaCTCorr, or by a delayed FileUp transcript containing that record, adds its encryption epoch to $\mathcal C$; the correct next-component guess from Step~1 has therefore protected that epoch from record creation. If its matching key has already been exposed, the execution is trivial and uses the independent-output abort. If no such direct exposure occurs, the destination may remain an ordinary real epoch, but the active record stays withheld. At a crossing its body remains uniform after the real public pad update, its header is an independent uniform value in the regime selected for the destination, and its opening is refreshed as described in Step~5. Ordinary records use the exact real update on internal edges and the joint real-destination simulation of Step~3 at the right boundary. Thus a sanitized active ciphertext is never returned together with its matching decryption key, while every exited or ordinary record remains valid.

\paragraph{5. Opening ciphertexts, including real-key boundaries.}
Process each active RISE ciphertext when it first enters the active set, including the freshly re-randomized output of the initial IND-REENC-CPA KeyUp, and then process fresh active ciphertexts one at a time. For a challenge triple $(Y,R,Z)$ with $R=rG$, form
\[
 C=(Z,\;R+M).
\]
In the real case $Z=rY$, so this is exactly $\mathsf{RISE.Enc}_Y(M)$. In the DDH-random case $Z$ is independent and uniform, and hence $C$ is a uniform pair independent of $M$. Honest KeyUp re-randomization makes this replacement exact in the real DDH case even when the predecessor ciphertext remains an ordinary real encryption. While the slot remains active inside $J$, apply the actual public update algorithm using the known internal ratios; fresh re-encryption and addition of independently encrypted opening deltas preserve a uniform pair independent of $M$. Ordinary proof ciphertexts, including pre-challenge candidate ciphertexts, retain their tracked plaintext openings and are never modified retroactively. At most $M$ DDH hops are needed in a component.

Three refresh observations make exits and boundaries exact. First, conditional on any previous valid ciphertext and its opening $M$, honest KeyUp adds independent encryption randomness, so its output is a fresh encryption of the new opening under the new public key. At a hidden boundary the simulator therefore samples an ordinary record's fresh encryption directly under the known destination public key; it does not need the cross-boundary secret ratio. For an ordinary record entering a real exposed epoch, the plaintext is the correct tracked opening and decryption under the revealed real key succeeds.

Second, an active ciphertext crossing that same hidden boundary is already uniform by the DDH hybrid. Applying the real update with fresh randomness would therefore again produce an independent uniform pair, even though the unknown ratio cannot be evaluated. The simulator samples that uniform pair directly. If the destination key is exposed, the active record is withheld; if it later leaves $\mathcal I$, the next refresh restores a valid ordinary ciphertext. Third, when an active slot is overwritten, the fresh encrypted FileUp delta makes the output in the original, unsanitized game a fresh valid encryption of the new opening, independent of the old active ciphertext. The simulator generates that fresh valid ciphertext directly, as stated in Step~4, rather than adding the delta to a sanitized ciphertext. These are distributional refresh steps, not assumptions that hidden tokens erase information.

Within $J$, disclosed tokens use the known ratios $d_t/d_{t-1}$ from Step~2. No RISE key in $J$ is returned. Outside $J$, KeyCorr returns the real independently sampled key. Hence every combination of disclosed internal tokens, hidden boundary tokens, and later real-key exposure is answered without knowing the embedded DDH root secret.

\paragraph{6. Adaptive opening-state alignment for IND-REENC-CPA.}
For this game we maintain an additional invariant between the two candidate histories. Write the current inner scalar as
\[
 u=f(\tau)+\varpi Z(\tau),
\]
where $\varpi$ accumulates the initial KHVC blind and all public $\xi$ and $\eta$ shifts. Before the challenged KeyUp, no active-set replacement is applied retroactively: both candidate repositories keep their tracked plaintexts and already returned wire records. If disclosure of the challenged transition puts a source epoch in $J$, Step~1 has generated that epoch from the outset with the component's shadow header and DDH-root public keys; its ordinary bodies and openings still retain their tracked plaintexts. At every KeyUp choose $\xi_0$ uniformly and set
\[
 \xi_1=\xi_0+\frac{u_0-u_1}{Z(\tau)} .
\]
This is a uniform bijection and gives $u_0'=u_1'$. Choose the same fresh private $\beta'$ in both histories; the new public stubs are then identical. Each $\xi_b$ is uniform and independent of the candidate source, so this coupling also has the correct distribution when the KeyUp transcript is disclosed. Its unordered, unlabeled format prevents any additional source label from being introduced.

At FileUp of a differing active slot, the replacement file and nonce are common, but the increments $d_0,d_1$ can differ. Use the $\eta$ bijection of Lemma~\ref{lem:joint-fileup-mask}. It preserves $u_0'=u_1'$ and makes all off-slot plaintext openings equal; the first such transcript is withheld by IND-REENC-CPA. Generate the still-active openings by Step~5 and the newly exited slot by a fresh valid encryption of its now-common opening. For a disclosed FileUp, the old and replacement digests agree in the two histories, so use identical $d_i$, $\eta$, and encryption coins. Lemma~\ref{lem:opening-continuation} is the inductive continuation statement for these steps. Equal fresh $\beta'$ values keep the stubs aligned throughout.

Once every differing slot has been overwritten, all current digests and valid visible openings agree. Before that point, active differing openings are uniform by DDH and are never returned under a matching exposed key. Later real keys outside protected components are identical in the two histories, and all ordinary records crossing into those epochs have the correct aligned plaintexts. Thus all continuation queries, including disclosed internal transitions and subsequent real-key exposure, preserve the invariant.

\paragraph{7. Delayed transcripts and random-oracle consistency.}
The private FileUp log contains the exact old wire record, the fresh payload message, $d_i$, $\eta$, public encryption keys, and the simulator's retained coins. ChaFTCorr returns precisely the public fields specified in Section~\ref{sec:optimized-uss}, without exposing retained coins or private offsets. If it exposes an old active record at epoch $t$, then $t\in\mathcal C$, and hence $t$ belongs to the component for which the record was created in the protected regime. No retroactive ciphertext replacement occurs. If a later real key is exposed across a hidden boundary, an overwritten slot has already exited $\mathcal I$ and its current payload and opening are valid under that key. The disclosed historical $d_i$ can reveal the old salted digest, but the transcript contains neither its nonce nor a subsequent freedom to change $\eta$. This handles every delayed disclosure allowed by $\mathsf G_{\mathrm{cl}}$.

Whenever $Z(\tau)\ne0$, fresh private offsets make newly created public stubs uniform in the real game and in the simulation. The exceptional setup event has probability at most $n/p$. Theorem~\ref{thm:hide} gives the initial position-hiding distribution, and Lemmas~\ref{lem:joint-fileup-mask} and~\ref{lem:opening-continuation} cover the subsequent algebraic updates.

For explicit oracle accounting, Store uses the ordinary real path outside a guessed component and the shadow/protected path inside it. Next updates every repository with the tokens from Steps~2--5 and returns all non-challenge repositories and every off-active challenge slot. FileUp verifies against the logical honest state, refreshes an overwritten active slot as in Steps~4--5, uses the real path for other slots, and appends the exact public transcript to the log. KeyUpTrans returns disclosed internal tokens with known body differences, shadow switching keys, and RISE multipliers; crossing tokens are withheld for a correct component guess. KeyCorr returns real outside keys, while a protected-key request causes the selective abort already analyzed. ChaCTCorr returns the logged active record and adds its epoch to $\mathcal C$; a matching exposed key makes the execution trivial and is covered by the independent-output abort. ChaFTCorr is exactly the logged disclosure above. Hence every oracle in $\mathcal O_{\rm full}$ is simulated online with no omitted query branch.

\paragraph{8. Finishing IND-DD-UP and IND-FileUp-CPA.}
Starting from either value of $b$, apply Steps~1--5 and~7. The challenge plaintext and its fresh nonce now occur only in the logical table, not in a returned payload or active opening. Replace the corresponding initial digest by an independent random-oracle answer, programming the random oracle if the hidden file-and-nonce input is later queried. Keep this digest fixed for the version's entire lifetime and derive every later $d_i$ and opening from it. Before an overwritten slot's transcript is disclosed, Lemma~\ref{lem:joint-fileup-mask} makes the joint distribution of all visible off-slot opening updates independent of its $d_i$, even under an available epoch decryption key; after disclosure, the logged values are used verbatim. Until the hidden file-and-nonce input is queried, the digest and all values derived solely from it are independent of $b$. Hidden-nonce collisions and adversarial guesses contribute at most $V(V+Q_{\rm ro})2^{-256}$. The two final simulations are then identical, and reversing the hybrid sequence with $b=1$ proves the claim.

\paragraph{9. Finishing IND-REENC-CPA and collecting the bounds.}
The pre-challenge candidate repositories retain their original plaintexts and wire records in the regime selected for their source epochs; in particular, a disclosed challenged transition causes no retroactive modification. Active updated headers, bodies, and proof ciphertexts are source-independent by Steps~3--5. Non-challenge slots initially have identical ciphertexts or later receive the same adversarial replacement. Step~6 aligns every visible stub and valid opening, while ChaFTCorr is absent and the only transcript containing an unequal $\eta$ is withheld. KeyCorr returns the actual identical real keys outside protected components, and no key is exposed inside such a component. Therefore the two final source-world views have identical distributions.

Collecting all component guesses and primitive hops gives the explicit, pessimistic bound
\[
\begin{aligned}
\operatorname{Adv}_{\rm conf}\le{}& E(E+1)^2\Big[2(E+DE+V+R)\epsilon_{\rm RLWE}
 +(V+R)\epsilon_{\rm RLWR}+M\epsilon_{\rm DDH}+\delta_{\rm stat}\Big]\\
 &+\frac{n}{p}+\mathbf 1_{\rm plain}\frac{V(V+Q_{\rm ro})}{2^{256}},
\end{aligned}
\]
where $\mathbf 1_{\rm plain}=1$ for IND-DD-UP and IND-FileUp-CPA and $0$ for IND-REENC-CPA. The factor $2$ covers both the shadow-header conversion and the subsequent active-header sanitization. The deterministic residual bounds and the wide-noise range make $\delta_{\rm stat}$ negligible for every polynomial query bound; the concrete 127-edge accounting is the bound given below Lemma~\ref{lem:hidden-rotation}. Every remaining factor is polynomial in the security parameter and each primitive advantage is negligible. The deterministic body and header inequalities provide correctness within the configured rotation budget; they are not an additional exposure or suffix restriction in the confidentiality game.
\end{proof}

\subsubsection{FileUp opening repair and adaptive exposure}
\label{sec:fileup-repair}

\paragraph{The earlier zero-blind variant.}
Before this repair, FileUp called $\mathsf{open\_one\_hot}(i,d_i,0)$ and refreshed only the client's private offset. Two FileUp calls in a later corrupted epoch then distinguished the source in IND-REENC-CPA. The query chain was Store two candidates and KeyCorr(1), challenge KeyUp to epoch 2, Next to epoch 3, KeyCorr(3), and FileUp at $j$ followed by FileUp at $i\ne j$. The first overwrite makes $j$ visible. The second returns an updated opening for $j$ even while withholding the transcript at $i$. Let
\[
 A_{i,j}=\left[\frac{L_{i-1}(\tau)}{\tau-\omega^{j-1}}\right]_1 .
\]
The two decrypted openings previously differed by $(h_i'-h_{i,b})A_{i,j}$. The known candidate digests could be tested by a group equality. This chain had $\mathcal C=\{2\}$, $\mathcal K=\{1,3\}$, and $\mathcal T=\emptyset$, so it passed the closure rule.

\paragraph{Repaired difference and correctness.}
The current difference is
\[
 D_j=(h_i'-h_{i,b})A_{i,j}+\eta W_j,\quad j\ne i .
\]
It includes a fresh independent $\eta$ for every accepted FileUp. On an undisclosed transcript $\eta$ is unavailable, even when the epoch RISE key is disclosed. Write the current inner commitment scalar as $u=f(\tau)+\rho Z(\tau)$. The plaintext opening stored at $j$ is
\[
 B_j=\left[\frac{u-h_j}{\tau-\omega^{j-1}}\right]_1 .
\]
After the update $u'=u+d_iL_{i-1}(\tau)+\eta Z(\tau)$. The client sets $C'=[u'+\beta'Z(\tau)]_1$, and adding $\beta'W_j$ to $B_j'$ is exactly the KHVC opening for $C'$. This establishes the same verification invariant at the overwritten slot and all off-slot positions. Verification of the old record still precedes every mutation.

\begin{lemma}[Joint off-slot mask when the FileUp transcript remains hidden]
\label{lem:joint-fileup-mask}
Fix the old opening state and the unchanged digests at all $j\ne i$. If the FileUp transcript at $i$ remains hidden and $\tau\notin\Omega$, the joint plaintext opening differences $(D_j)_{j\ne i}$ have a distribution independent of $d_i$. This remains true with the old openings and the epoch decryption key available.
\end{lemma}
\begin{proof}
Set $a=d_iL_{i-1}(\tau)+\eta Z(\tau)$. Because $Z(\tau)\ne0$ and $\eta$ is uniform, $a$ is uniform in $\mathbb F_p$ for every $d_i$. Every off-slot difference is $[a/(\tau-\omega^{j-1})]_1$. These differences are correlated through $a$, and their joint distribution, not only each marginal, is independent of $d_i$. For two possible increments $d_0,d_1$, the bijection
\[
 \eta_1=\eta_0+(d_0-d_1)\frac{L_{i-1}(\tau)}{Z(\tau)}
\]
gives identical off-slot difference tuples. The setup trapdoor appears only in this distributional argument.
\end{proof}

\begin{lemma}[Adaptive continuation of aligned opening states]
\label{lem:opening-continuation}
Consider two challenge repository histories with the same visible slot digests. At an epoch boundary suppose their inner scalars $u_0,u_1$ are aligned, and their visible opening ciphertexts and stubs have already been coupled. The active slots in $\mathcal I$ may have different digests. Restrict transcript disclosures at each step as follows: an overwrite of a differing active slot has a transcript that remains undisclosed, while a disclosed FileUp has the same old and replacement digests in both histories. Other oracle outputs, including payloads, are assumed already coupled. Suppose also that every revealed ciphertext in this continuation is for a slot with equal current digests in the two histories. Then all visible stubs and opening ciphertexts in this continuation can be coupled under adaptively chosen FileUp, KeyUp, and key-exposure queries. The epoch keys and public transition ratios can be the actual, identical values in the two histories, including keys exposed in components disconnected from the initial challenge exposure. The assertion concerns this continuation and does not construct the initial aligned state or simulate payload ciphertexts.
\end{lemma}
\begin{proof}
Maintain $u_0=u_1$, equal digests at visible slots, and the identical wire replies seen so far. Use identical private offsets for the coupled stubs. At a FileUp of a differing active slot, couple its replacement file and nonce, and hence its new digest. The two increments $d_0,d_1$ may differ. Sample $\eta_0$ uniformly and set $\eta_1$ by the bijection in Lemma~\ref{lem:joint-fileup-mask}. This preserves $u_0'=u_1'$ and gives equal new openings at all returned slots, including the just-overwritten slot, whose replacement digest is now equal. Sample equal fresh RISE ciphertexts of these equal openings. This is the real joint distribution conditional on each world's previous ciphertexts: independent delta encryptions make every resulting ciphertext a fresh encryption of its new opening. All hidden fields and logs are retained privately in their respective worlds.

For a disclosed FileUp, the increments agree, so use the same $\eta$ and the same ciphertext coins. Return the exact stored transcript on later identical requests. KeyUp uses equal $\xi$ and epoch keys, preserving $u$ alignment. Couple the resulting fresh RISE encryptions of equal visible openings; their refresh coins may differ if the previous hidden ciphertexts differed. Hidden slots remain hidden, and already visible slots have equal plaintext openings, so their wire updates can again be coupled. KeyCorr returns the actual identical epoch secrets. There is no altered public key that subsequently has to be explained by a different secret. ChaCTCorr at an epoch with an exposed matching key and an active differing slot would violate the closure check. Even at an epoch without such a key, a disclosure of a differing slot falls outside this lemma and requires a separate RISE reduction. Adaptive choices agree because the visible replies agree at every preceding step. A later disclosure of a previously unequal $\eta$ would invalidate the premise, so the lemma explicitly excludes it.
\end{proof}

\paragraph{Application to the full opening-layer reduction.}
In IND-REENC-CPA, ChaFTCorr is absent and the first overwrite of an active differing slot withholds its transcript. Thus the repaired mask supplies precisely the continuation step needed after such a slot becomes visible under a later leaked key. Step~6 of Theorem~\ref{thm:adaptive-full} constructs the initial aligned state by a uniform $\xi$ bijection; this coupling remains valid whether or not its transcript is disclosed. Step~5 separately supplies the component-wise DDH argument for all earlier active ciphertexts. Consequently the continuation lemma is applied only after both its initial-state and ciphertext hypotheses have been established.

\paragraph{Delayed transcripts in the plaintext games.}
IND-DD-UP and IND-FileUp-CPA have ChaFTCorr. An overwrite at epoch $t$ may be followed by disclosure of its recorded transcript, a Next query, and KeyCorr($t+1$) with the connecting token withheld. The replacement is off-challenge and decryptable at $t+1$, so its digest $h_i'$ and the historical $d_i$ give $h_i=h_i'-d_i$. This chain is allowed by closure when only the old challenge record at epoch $t$ was exposed. Steps~4,~5, and~7 of Theorem~\ref{thm:adaptive-full} create the protected record before its disclosure is known, restore a valid fresh record when the slot exits $\mathcal I$, and return the original logged $d_i$ and $\eta$. In the random-oracle model the disclosed salted digest does not reveal the fresh challenge nonce, and the completed payload hybrids remove every other dependence on the challenge plaintext.

\paragraph{Why shadow headers are necessary.}
Keeping ordinary records real does not justify replacing one fresh header term by uniform while retaining a real public key and real switching material. If $(a,b=ax+e)$ is the real public key and $(U,V)=(ar+e_1,br+e_2)$ is the fresh term, then
\[
 V-xU=er+e_2-xe_1.
\]
A bare two-sample Ring-LWE hop does not give the reduction the old secret $x$ needed to generate the outgoing switching key. The right-to-left construction in Theorem~\ref{thm:adaptive-full} first removes this dependency on internal edges: the outgoing edge already encrypts the simulator-chosen $\widetilde x_t$ under the next shadow secret. Only then does it replace the public key, each fresh term, and finally the incoming edge and current records. Thus no unknown real public-key secret is retained while its fresh term is changed. The final right boundary is handled separately by the joint real-destination simulation.

A legal boundary query pattern illustrates why this matters: Store an ordinary repository and issue a DD-UP challenge in epoch 1, execute Next to epoch 2 without requesting the connecting token, return every ordinary update, and then reveal the epoch-2 key. This has $\mathcal C=\{1\}$, $\mathcal K=\{2\}$, and $\mathcal T=\varnothing$. The full proof applies Lemma~\ref{lem:hidden-rotation} to simulate every ordinary header and body jointly under the real, subsequently revealed epoch-2 key. Neither this statistical step nor the shadow-header reduction assumes that withholding the token removes its effect on ordinary records.

\paragraph{What the repairs establish.}
The former two-FileUp source test is blocked by Lemma~\ref{lem:joint-fileup-mask}, and the aligned-state continuation handles later real key disclosure after the DDH and alignment steps. The wide-noise construction gives the explicit multi-file statistical bound of Lemma~\ref{lem:hidden-rotation} and deterministic 127-rotation correctness checks. Together with the body, delayed-transcript, and opening reductions, these repairs support the full adaptive confidentiality conclusion of Theorem~\ref{thm:adaptive-full}. Theorem~\ref{lem:ofptxt} remains a separate integrity result and does not rely on any confidentiality-game exposure exclusion.

\begin{theorem}[OF-PTXT with verified FileUp]
\label{lem:ofptxt}
The construction satisfies Definition~\ref{def:of-ptxt} under KHVC position binding and $\mathsf{COM}$ binding. This guarantee permits exposure of every epoch secret. The client retains its current stub and private offset, and uses them rather than accepting a server-supplied replacement for either value.
\end{theorem}
\begin{proof}
Track the latest accepted file and digest at each slot. At Store, the stub commits to these digests. At KeyUp, the stub changes only by a multiple of $Z$, so the digest vector is invariant. At FileUp the client verifies the old record before generating any update. If the accepted digest differs from the tracked digest, the corrected opening $P+\beta W_i$ and an honest opening give a KHVC position-binding violation. If the accepted plaintext differs while the digest agrees, the two file-and-nonce inputs give a $\mathsf{COM}$ binding violation. Outside these events the digest subtracted by the honest client is the tracked digest. Both the stub update and the encrypted opening update include the same $\eta Z$ term, so the client correction by $\beta'W_i$ makes every opening agree with the new stub and the updated digest vector. At the final Rev the same two cases apply to any accepted stale or forged plaintext. The reduction computes the honest openings from the tracked vector and the client's chosen blinding; neither server behavior nor leakage of epoch decryption keys affects that computation.
\end{proof}
