## 2. 方案简介

### 2.1 什么是向量承诺（Vector Commitment）

向量承诺允许对一个属性向量 \(\mathbf{m}=(m_0,\ldots,m_{n-1})\) 生成一个短承诺 \(C\)，并在事后对任意位置 \(i\) 打开并证明 \(m_i\)，而无需暴露其余属性。测评场景中，“100 个属性值”即向量长度至少为 100 的消息向量。

### 2.2 本库采用的方案：KHVC

本库实现的 **KHVC** 是一种基于 **KZG 多项式承诺**、运行于 **BLS12-381** 配对曲线上的**同态向量承诺**：

1. **编码**：将属性向量插值为次数小于 \(n\) 的多项式 \(f(X)\)，使得在 \(n\) 次单位根 \(\omega^i\) 上满足 \(f(\omega^i)=m_i\)。
2. **隐藏**：采样随机盲化因子 \(\rho\)，构造 \(F(X)=f(X)+\rho\cdot Z(X)\)，其中 \(Z(X)=X^n-1\) 为消失多项式。
3. **承诺**：\(C=[F(\tau)]_1\in\mathbb{G}_1\)，其中 \(\tau\) 为结构化参考串（SRS）陷门。**承诺恒为单个群元素**，压缩后固定为 **48 字节**，与属性个数无关（只要在所设维度 \(n\) 内）。
4. **打开与验证**：对位置 \(i\) 生成 KZG 型打开证明 \(\pi_i\)，通过配对等式验证。
5. **同态性**：支持承诺同态 `ComHom` 与打开同态 `OpenHom`，便于上层可更新安全存储（USS）等应用组合更新。

### 2.3 相对传统方案的优势（便于理解库的定位）

| 对比项 | Catalano–Fiore 型 HVC（库内 `cf_hvc` 基线） | 本库 KHVC |
|--------|---------------------------------------------|-----------|
| SRS / 公开参数规模 | \(O(n^2)\)，\(n=1024\) 时约数十 MB | \(O(n)\)，\(n=1024\) 时约数十 KB |
| 承诺尺寸 | 常数（约 48 B） | 常数（**48 B**） |
| 承诺时间 | 随 \(n\) 增长较快 | 毫秒级（100 属性远低于 5 秒） |
| 位置绑定 | 有 | 在 \(q\)-SDH 假设下可证明 |
| 位置隐藏 | 有 | 统计隐藏（至多 \(n/p\) 的 Setup 坏事件） |

> 说明：指标 3.4 仅考核“向量承诺开源库”的承诺尺寸与承诺时间；库内同时提供 CF-HVC 对比基线、USS 等扩展模块，**不纳入本指标必测范围**，测评时可只关注 KHVC。

### 3.2 核心 API（`impl/src/khvc.rs`）

| 接口 | 作用 | 测评相关性 |
|------|------|------------|
| `Khvc::setup(n, rng)` | 生成维度为 \(n\) 的公开参数（要求 \(n\) 为 2 的幂且 \(n\ge 2\)） | 预处理；不计入“承诺时间” |
| `Khvc::commit(values, r)` | 对长度为 \(n\) 的属性向量生成承诺 | **承诺时间 / 承诺尺寸** |
| `Khvc::open(i, values, r)` | 打开第 \(i\) 个属性 | 正确性抽查 |
| `Khvc::verify(c, value, i, opening)` | 验证打开证明 | 正确性抽查 |
| `Khvc::com_hom` / `open_hom` | 同态组合 | 功能完整性 |
| `Khvc::open_all` / `open_one_hot` | 批量 / 单点稀疏打开优化 | 扩展功能 |

**承诺尺寸说明**：承诺类型为 `Commitment(G1Projective)`，经 BLS12-381 \(\mathbb{G}_1\) **压缩序列化**后固定为 **48 字节**（远小于 2 KB）。

**100 个属性的约定**：KHVC 内部评估域长度须为 2 的幂。测评 100 个属性时取 \(n=128\)，将 100 个属性写入前 100 个槽位，剩余 28 个槽位填 0。该做法等价于“支持至少 100 个属性值的向量承诺”，且不改变承诺尺寸（仍为 48 字节）。

### 3.3 运行环境建议

- 操作系统：macOS / Linux
- 语言工具链：Rust（建议 `rustc` / `cargo` 1.70+）
- 构建：Release 模式（`-C opt-level=3`，即 `cargo run --release`）
- 曲线与库：`ark-bls12-381` 0.5（配对友好曲线，业界常用）

### 步骤 3：运行指标 3.4 专用验收（尺寸 + 时间）

```bash

```

**通过判定**：

1. `num_attributes=100`
2. `pass_size=true`（`commit_size_bytes ≤ 2048`）
3. `pass_time=true`（`commit_avg_s ≤ 5`）
4. `open_verify_ok=true`

### 步骤 4（可选）：更大维度微基准

```bash
cargo run --release --bin bench -- --suite hvc --smoke
```

输出 CSV 中筛选 `scheme=KHVC` 且 `op=commit` 的行，确认 `bytes=48` 且 `ms` 远小于 5000。

### 测评关注点建议

1. **只计 Commit**：Setup 为一次性参数生成，验收指标中的“承诺时间”指 `commit` 本身。
2. **尺寸口径**：以压缩序列化后的承诺字节数为准（本库 48 字节）；不应把 SRS/CRS 计入“承诺尺寸”。
3. **属性个数口径**：100 个有效属性 + 零填充至 \(n=128\) 为合法测评配置。
4. **机器差异**：不同 CPU 上毫秒数会有波动，但相对 5 秒上限通常仍有数千倍余量。

## 7. 安全性质摘要（供专家背景阅读）

- **位置绑定（Position Binding）**：在 \(q\)-SDH（\(q=n\)）假设下，攻击者难以对同一承诺、同一位置给出两个不同属性值的有效打开。
- **位置隐藏（Position Hiding）**：除 Setup 时 \(\tau\in\Omega\) 的可忽略概率外，承诺与无关位置的打开在统计上不泄露被隐藏位置的信息。
- **同态性**：\(\mathsf{ComHom}/\mathsf{OpenHom}\) 与底层群加法一致，支持增量更新场景。

更完整的形式化定义与证明见仓库 `paper/main.tex`（英文论文）。
